# ADR-0011: Built-in effects with declarative parameters and a closed property vocabulary

- **Status:** Proposed
- **Date:** 2026-10-28
- **Related:** [ADR-0004](0004-open-project-format.md), [ADR-0008](0008-render-and-audio-engine.md), [ADR-0015](0015-clean-room-policy.md), private research: `docs/capcut-rea/RESOURCES.md`, `docs/capcut-rea/DRAFT-FORMAT.md`

## Context

In CapCut, effects, filters, transitions and text templates arrive as downloadable catalog items, so a project renders only where those items are available. Animation in professional editors works on a fixed set of animatable properties, and animated captions need per-word timing and range-based animators. For agents, the key need is that every effect has a documented type, a parameter schema with ranges and units, and a stable path for keyframes, so an agent can set and animate parameters without guessing.

## Decision

1. **Effect types are registered in code** with a manifest: `type` (namespaced, for example `color.hsl`, `mask.ellipse`, `blur.gaussian`, `transition.crossfade`), `version`, inputs (one for filters, two for transitions), parameters (name, type, default, range, unit, animatable flag, description), and WGSL passes. The registry is exported through `capabilities` so agents discover effects and their schemas at runtime.
2. **Effect instances** are stored as `{id, type, version, enabled, params, keyframes}` inside the owning clip, track or adjustment layer ([ADR-0004](0004-open-project-format.md)). Unknown types or newer versions fail validation with a clear error.
3. **Closed animatable property vocabulary.** Every animatable value has a path: `transform.position`, `transform.scale`, `transform.rotation`, `opacity`, `volume`, `effects.<id>.<param>`, `text.runs.<n>.color`, and so on. Keyframes are `{time, value, interpolation}` with interpolation `hold`, `linear`, or `bezier` with explicit control points. The list of paths is generated from the model and published with the schema.
4. **Initial built-in set** (reimplemented from public formulas): transform and crop; opacity and 11 blend modes (normal, multiply, screen, overlay, darken, lighten, color dodge, color burn, hard light, soft light, linear burn); masks (rectangle, ellipse, linear, mirror, polygon/pen, text) with feather, expansion, round corners, invert, multiple masks per clip; chroma key; color (exposure, temperature, tint, contrast, saturation, highlights, shadows, whites, blacks, curves, HSL in eight bands, color wheels, LUT `.cube` import, vignette, sharpen, grain); blur; speed ramps; transitions (crossfade, dip, push, slide, wipe, zoom); adjustment layers.
5. **Text and captions** get a dedicated engine: styled runs, per-word timing from transcripts, and animators with range selectors (by character, word, line), expressions limited to a safe declarative set, and presets. This is the backbone of "viral" captions.
6. **Third-party effects later, sandboxed:** user effect packages may contain only a manifest and WGSL (no scripts) so they are portable and safe. OpenFX plug-in hosting for native desktop plug-ins is a later, optional feature behind a feature flag.
7. **Presets are data.** Looks, text styles and animation presets are JSON documents over the same parameter vocabulary, shipped with clear licenses and provenance.

## Implementation notes

- **Text, first step** (milestone 3): text clips render as layers in `fosscut-render`. `cosmic-text` shapes and wraps the text with only the bundled Inter fonts (Regular, Bold, Italic, Bold Italic; SIL Open Font License, provenance in `crates/fosscut-render/assets/fonts/inter/README.md`), never system fonts, so text renders identically everywhere. Size is a fraction of the canvas height, lines wrap at 90% of the canvas width and align within the text block, and colors are sRGB hex decoded to linear light. Text is rasterized on the CPU at the output resolution (sharp in preview and export) and composited as a premultiplied layer with the clip's transform, opacity, mask and LUT. Placement centres the exact layout box rather than the pixel-cropped raster, so text keeps its position at every output size; styled runs come later.
- **Captions** (milestone 6): per-word timing, word animators, caption presets and safe areas are decided in [ADR-0021](0021-captions-as-timed-word-clips.md).
- **Clip properties and keyframes** (format 0.3.0, item 3):
  - **Vocabulary:** `fosscut_model::clip_properties()` is the closed list, published by `capabilities` as `properties` with each path's kind, range, choices and whether it takes keyframes. Paths: `transform.position`, `transform.scale`, `transform.stretch` (per-axis factors on top of the uniform scale), `transform.rotation`, `transform.flip_horizontal`, `transform.flip_vertical`, `crop.left`, `crop.right`, `crop.top`, `crop.bottom`, `opacity`, `blend`, `enabled`, `volume`, `audio.pan`, `audio.fade_in`, `audio.fade_out`, `audio.channels`.
  - **Storage:** a clip's `keyframes` map holds a list per animatable path, sorted by time, one keyframe per time. Times are offsets from the clip's start, so keyframes move with the clip. Splits, trims and range cuts keep every keyframe and only shift times, so the curve stays exact on both sides of a cut.
  - **Interpolation:** `hold`, `linear` (the default, omitted) or `{"bezier": [x1, y1, x2, y2]}` as in CSS. Commands also take the names `ease_in`, `ease_out` and `ease_in_out`. Values hold before the first keyframe and after the last.
  - **Commands:** `clip.set` sets plain values by path. It refuses an animated property with `fosscut.clip.property_animated`. `keyframe.set` adds or replaces a keyframe; without a value it keeps the current animated value. `keyframe.remove` removes one keyframe, or all of them (keeping the value at a given time).
  - **Crop:** removes edges without moving what remains. Edges are measured on the picture before flips.
  - **Blend modes:** the eleven of item 4 plus add, difference and exclusion. Every mode but normal uses the separable formulas of the W3C Compositing and Blending specification on sRGB-encoded values, then decodes back to linear light. Runs of normal layers still draw in one multisampled pass; a blended layer is drawn alone and combined with the canvas in a full-screen pass. Tests check every mode against the formulas, with a reviewed golden frame.
  - **Deactivated clips:** a clip with `enabled: false` keeps its place but is neither drawn nor heard.
- **Masks** (format 0.5.0, item 4): a clip's `masks` list combines in order.
  - **Shapes:** `rectangle` (round corners), `ellipse`, `linear` (one side of a line), `mirror` (a band), `star`, `heart`, `path` (the pen: points with optional Bezier handles), `text` and `brush` (painted and erasing strokes).
  - **Placement:** each mask has a centre and size as fractions of the picture, a rotation, feather, expansion, `invert`, `enabled`, and a mode (`add`, `subtract` or `intersect` with the masks before it). Positions follow the picture as displayed, after its display rotation.
  - **Keyframes:** centre, size, rotation, feather, expansion and roundness animate with `keyframe.set` as `masks.<id>.<property>`. Commands are `mask.add`, `mask.set` and `mask.remove`; mask ids (`mask_…`) are renewed for copies like effect ids.
  - **Rendering:** masks rasterize on the CPU into one coverage image of the picture (at most 768 pixels on its longest side, cached while unchanged), which the composite multiplies into the layer's alpha. Shapes are signed distances in units of the picture's height, so feather and expansion mean the same at any size. Stars and hearts are traced polygons, paths flattened Bezier curves, and text is rasterized with the bundled font to fill the mask's box.
  - **Adjustment masks:** on an adjustment clip the masks are measured over the canvas and limit where its effects mix in.
- **Transitions** (format 0.6.0, items 1 and 4): a clip's `transition` leads into the next clip on its track, which must start where it ends.
  - **Types:** `fosscut_model::transition_types()`, published by `capabilities` as `transitions`: `dissolve`, `dip` (through a color, black by default), `wipe` (direction, softness), `slide` and `push` (direction), `zoom`, `blur`, `iris` and `clock` (softness), and `spin`. Parameters use the effect parameter kinds.
  - **Timing:** a transition lasts its `duration` (half a second by default, at most the shorter clip), centred on the cut, so the edit keeps its length. The outgoing clip plays on past its end and the incoming one starts early, both held at their media's ends when there is no more.
  - **Commands:** `transition.set` adds or replaces one (`fosscut.transition.unknown_type`, and `fosscut.transition.no_neighbor` when no clip starts at the cut); `transition.remove` takes it away. A split keeps it on the right part, and a range cut on the piece that still ends at the original cut.
  - **Rendering:** while it lasts, the planner puts one transition layer in place of both clips. Each side renders with its own transform, effects and masks into a texture of the canvas, then one pass (`fs_transition` in `shaders/effects.wgsl`) combines them by progress and the result draws over the layers below. The sound crossfades with equal power over the same span.
- **Clip animations** (format 0.6.0, item 4): a clip's `animations` hold an entrance (`in`), an exit (`out`) and a repeating `combo`, each a preset with a duration.
  - **Presets:** entrances and exits are `fade`, `slide_left`, `slide_right`, `slide_up`, `slide_down`, `zoom_in`, `zoom_out`, `spin`, `pop` (a damped spring) and `drop` (a bounce); combos are `pulse`, `swing`, `float` and `shake`. An exit plays its preset backwards up to the clip's end. `capabilities` lists them as `animations` with where each applies.
  - **Evaluation:** `fosscut_model::animate` gives an offset, scale, rotation and opacity that multiply or add on top of the clip's own, keyframed placement. They are presets in code, not stored keyframes, so changing a clip's length keeps them at its edges.
  - **Commands:** `animation.set` sets any of `in`, `out` and `combo` (half a second, or a second per combo cycle, by default) and `clear` removes them. A split keeps the entrance on the left part and the exit on the right; combos stay on both.
  - **Motion-design presets** (format 0.16.0): entrances made for motion graphics, `blur_in` (into focus from a blur), `pop_in` (from 60% past full size, with the back ease-out of Robert Penner's easing equations), `rise_in` (a short way up), `swoop_in` (on a curve from the lower right, turning upright) and `glow_in` (a flare of light that peaks halfway), each with an exit counterpart (`blur_out`, `pop_out`, `rise_out`, `swoop_out`, `glow_out`) applying only as an exit. They are appended to the preset list; `capabilities` lists each with its place. Besides offset, scale, rotation and opacity, an animation may now blur (a fraction of the canvas height at the clip's own size) and glow (0 to 1): the planner adds them after the clip's own effects as an internal `animation.blur` (a Gaussian blur on a padded picture, like the light effects below) and an ordinary `light.glow`, so preview, frame grabs and export draw them the same way.
  - **Delays and staggers:** each animation has an optional `delay` (zero, and omitted, by default). An entrance holds its first state until the delay has passed, an exit ends the delay before the clip's end and holds its last state after, and a combo starts its cycles that late. `clips.stagger` sets one preset on several clips (of any timelines), each with a delay one `step` longer than the one before (a tenth of a second by default, after an optional `start`), in an `order`: as listed, reversed, by start time, by position on the canvas at the clip's start (`left_to_right`, `right_to_left`, `top_to_bottom`, `bottom_to_top`, `center_out`; ties keep the listed order) or `random` (a SplitMix64 shuffle by `seed`, the same everywhere). For exits the first in order waits longest, so it leaves first. It refuses a clip listed twice, a preset that does not fit the place, a negative step and an entrance or exit that would not finish within its clip, changing nothing (`fosscut.request.invalid_arguments`). CLI: `fosscut clips stagger`, `fosscut animation set --in-delay`; MCP: the `edit` tool.
- **Stylizing and moving effects** (format 0.6.0, item 4): `stylize.glitch`, `stylize.rgb_split`, `stylize.pixelate`, `stylize.vhs`, `stylize.mirror` (a half or a quarter reflected), `stylize.posterize`, `stylize.invert`, and in a new `motion` category `motion.shake`, `motion.zoom_blur`, `motion.flash`, `motion.rainbow` and `motion.zoom_pulse`. Effects that change over time read the time from the clip's start, so a frame renders the same every time; those with an `amount` leave the picture unchanged at zero.
- **Effects** (format 0.4.0, items 1, 2, 4 and 7):
  - **Registry:** `fosscut_model::effect_types()` lists each type with its version, title, category and parameters. A parameter has a kind (number, pair, bool, choice, curve or asset), a default, a range, a unit and whether it is animatable. `capabilities` publishes it as `effects`. The first types are `color.adjust`, `color.curves`, `color.hsl` (eight bands), `color.wheels` (lift, gamma, gain, offset), `color.lut`, `color.vignette`, `blur.gaussian`, `detail.sharpen` and `stylize.grain`. Effects that read neighbouring frames (`motion.blur`, `detail.denoise`, `color.deflicker`) follow ADR-0035.
  - **Instances:** a clip's `effects` list holds `{id, type, version, enabled, params, keyframes}` in the order they apply. `params` keeps only values that differ from the defaults. Unknown types, newer versions, unknown parameters and out-of-range values fail validation. Effect ids (`effect_…`) are unique in a project, so splits, cuts and copies give the copies new ids.
  - **Commands:** `effect.add`, `effect.set` (values, resets, bypass), `effect.remove`, `effect.move` and `effect.copy` (apply one clip's effects to others). Numeric parameters animate with `keyframe.set` as `effects.<id>.<param>`.
  - **Adjustment layers:** an `adjustment` clip on a video track has effects but no picture. `adjustment.add` puts it on an adjustment track above every video track, so titles and captions above stay as they are. While it lasts, its effects apply to the canvas composed below it, mixed back by its opacity.
  - **LUTs:** `.cube` files import as `lut` assets (`media import`, `media_import`) with their table size checked; `color.lut` names one, with an intensity and skin-tone protection. Exports check that the files exist before rendering.
  - **Looks** (item 7): built-in looks such as `warm`, `teal_orange`, `vintage` and `noir` are JSON documents of ordinary effects with chosen parameters, written for FossCut and published in `capabilities`. `look.apply` copies them into a clip, so a project never depends on the look afterwards.
  - **Rendering:** effects run on each layer's texture at its own size before placement, one full-screen pass per effect (`shaders/effects.wgsl`), then the result is mipmapped for compositing. Exposure, white balance and vignetting multiply linear light; tone, curves, HSL, wheels and grain work on sRGB-encoded values; LUTs on the BT.709 signal, as before. Curves interpolate with monotone cubics (Fritsch and Carlson), so they never overshoot. Blurs are separable Gaussians that sample a mip level needing at most 24 taps. Sharpening adds the difference from a blur. Grain is seeded by the frame, so a frame renders the same every time. Every effect leaves the picture unchanged at its defaults, which the tests check.
  - **Chroma key** (format 0.5.0): `key.chroma` removes a color (a new `color` parameter kind, `#RRGGBB`, green by default). Pixels whose chroma (BT.709 Cb and Cr) lies within the similarity of the key's become transparent, fading over the smoothness. Spill removal takes the key's chroma out of what stays.
  - **Automatic color** (ADR-0012: measured locally, no model): `fosscut_engine::color` renders seven frames of a clip without effects and measures their mean color, median, 1st and 99th luma percentiles and colorfulness. `color.auto` adds a `color.adjust` first in the clip's effects: a partial gray-world white balance, median brightness towards middle gray, and levels stretched only when the picture has a real tonal range. `color.match` adds one that brings the channel balance, brightness, spread and colorfulness close to a reference clip. Both are engine operations (`fosscut color auto|match`, the MCP `color` tool, the desktop's Auto color and Match color) that end in an ordinary `effect.add`, so they are undoable.

- **Light effects** (format 0.16.0, items 1 and 4): a `light` category with `light.glow`, `light.sweep` and `light.streaks`, for any picture clip; their numbers take keyframes. Formulas are public ones, written for FossCut in `fosscut-render`'s `light` module and `shaders/light.wgsl`:
  - **Glow:** a bright pass (a soft knee 0.1 below `threshold` on the brightest sRGB-encoded channel; 0 lets everything glow) turned towards `color` by `tint`, then Gaussian blurs at `radius` and a quarter of it (multi-scale bloom), added to the picture with `intensity`. Over transparent parts the light covers as much as its brightest channel, so it shows on the layers below; `glow_only` shows the light alone.
  - **Sweep:** a band (`width` a fraction of the distance it travels, a smoothstep edge by `softness`) moving in the direction `angle` from just before the picture (`position` 0) to just after it (1), adding `color` times `intensity` to visible pixels only.
  - **Streaks:** the brightest of the bright-pass samples along `angle` on both sides with an exponential fall-off (about 2% at `length`), in a fine and a coarse pass whose weights multiply into one curve (after Kawase's streak filter, GDC 2003); they are drawn on until their light falls below a thousandth, so bright streaks never end in a cut.
  - **Units:** radius and length are fractions of the canvas height and width measured at the layer's own size (its fitted size for video, images and compound clips; its raster for text, shapes and captions), so a glow looks alike on a title, a logo or a video and scales with the layer. Sweep and streak angles turn with a source's display rotation. Nothing is random.
  - **Padding:** glows, streaks and animation blurs spread past the layer: its picture is copied into the middle of a larger transparent one, and the effects from the first spreading one run on it, its quad growing past every uncropped edge with texture coordinates moved accordingly, so the layer keeps its place, size and masks (cropped edges still cut the light; layers placed in 3D are projected the same way). The padding goes after the last effect that reads cached analyses or neighbouring frames (`key.subject`, `body.*`, `motion.blur`, `detail.denoise`, `color.deflicker`), which line up with the unpadded picture; a spreading effect before one of them stays within the picture. Effects after the padding see the padded picture, with blur radii rescaled so they blur as much. A padded picture holds at most 4096 by 2048 pixels and stays within the device's texture limit, beyond which the light is cut; its outline is filtered in its own pixels, so a magnified picture's edge may soften by up to half of one of them. Adjustment layers are never padded: their light stays within the canvas.
  - **Tests:** unit tests of reach, padding, placement and packing; GPU tests that glows spread on every side without moving the picture (rotated, stretched, flipped, cropped and turned sources), that thresholds pick highlights, sweeps light only visible pixels and streaks follow their angle; preview and export parity for padded light on video and an animated glow on text; reviewed goldens `light-effects.png` (each effect at its defaults and extremes) and `glowing-end-card.png` (a glowing title and a sweep at two keyframes).
- **Styled text** (format 0.11.0, item 5): spans, reveals by letter, word or line, spacing, outlines, boxes, shadows, glows and project fonts are decided in [ADR-0027](0027-styled-text-with-project-fonts.md); built-in text presets and title templates are data in `fosscut-core/presets/text/`.
- **Sound effects** (format 0.11.0, item 1): `audio.denoise`, `audio.enhance_voice` and `audio.vocals` are registry types of the `audio` category, applied by the mixer, as decided in [ADR-0026](0026-sound-effects-in-the-effect-registry.md).

## Consequences

- Agents can enumerate effects and parameters, and invalid values are rejected before rendering.
- Projects remain renderable on any machine, because effects are code plus parameters, not downloaded binaries.
- A large built-in set is work; it is ordered by the roadmap and by what skills need first (captions, transforms, color, transitions, speed).

## Alternatives considered

- **Downloadable vendor packages with embedded scripts:** flexible but opaque, insecure for third-party content, and ties projects to a cache.
- **Open-ended keyframable paths:** easier to extend but impossible for agents to discover or validate.
- **A general node-graph compositor exposed to users:** powerful, but a poor fit for short-form editing and for agents; internal render plans can still be graphs.

## Validation

Golden-frame tests for every effect at default and extreme parameters; a schema test proving every animatable path in the registry resolves on a sample project.
