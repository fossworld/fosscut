# ADR-0039: Render web compositions in a headless browser, and the user's own Remotion on request

- **Status:** Proposed
- **Date:** 2026-11-01
- **Deciders:** maintainers
- **Related:** [ADR-0002](0002-agent-first-command-api.md), [ADR-0004](0004-open-project-format.md), [ADR-0006](0006-agent-safety-contract.md), [ADR-0008](0008-render-and-audio-engine.md), [ADR-0009](0009-media-io-and-codecs.md), [ADR-0012](0012-ai-capabilities-bring-your-own-brain.md), [ADR-0014](0014-licensing.md), [ADR-0020](0020-speech-recognition-with-whisper-cpp.md), [ADR-0032](0032-keep-proxies-remuxes-and-rendered-frames-as-caches.md), [ADR-0033](0033-run-local-vision-and-voice-models-with-onnx-runtime.md)

## Context

Motion-graphics ads show app mockups: a phone whose search bar types, product grids, buttons and toasts. Agents write HTML, CSS and JavaScript animation well, so a clip that shows an HTML page is an escape hatch for anything FossCut's own layers cannot draw yet. A page must render the same frame every time it is asked, in preview, frame grabs and exports alike (ADR-0008), and it must not reach the network or files outside its folder (ADR-0006, item 10).

Remotion renders React compositions to video, but it is source-available under its own licence, which requires a paid company licence above a small company size: a field-of-use restriction that ADR-0014 does not allow in distributed builds. Browsers are large and must not ship with FossCut either; Google Chrome is on most machines, and Chrome for Testing publishes a headless shell per platform.

## Decision

1. **Web assets** (`AssetKind::Web`, format 0.16.0, additive). A folder with an `index.html`, or one `.html` file, is copied into the bundle's `web/<first 16 hex of its hash>/` folder (hidden files and `node_modules` are skipped; at most 10000 files and 1 GiB). Its content identity is the total size and a BLAKE3 hash of every file's relative path, size and bytes in path order, so the same content imports once. `info.video` holds the size and frame rate (`codec` and `container` are `html`) and `info.duration` the length, a whole number of frames. Values come from the import arguments, else from `<meta name="fosscut:composition" content="width=1080, height=1920, fps=30, duration=6">` (`fps` a whole number or fraction, 30 when absent; `duration` in seconds, or with a unit such as `180f`). Width, height and duration are required (`fosscut.web.composition_unknown`). A page that loads scripts, styles, fonts or pictures from `http(s)` fails import with `fosscut.web.remote_reference`.
2. **Web clips are video clips.** `clip.add` of a web asset makes `ClipContent::Video`; `AssetKind::is_video` covers both kinds wherever video clips are checked. Source positions, speed, splits, trims, replacement, effects, masks, transitions, 3D placement and the frame cache (ADR-0032) apply unchanged. Web assets have no sound. Proxies, remuxes and video analyzers stay for video files.
3. **Frames.** `fosscut_engine::web::open_decoder` opens a `WebDecoder` for web assets wherever the engine opens decoders (export, frame grabs, preview). It starts a browser (item 5) with a fresh profile, loads the page once at a made-up origin (`https://composition.fosscut.invalid/`), answers every request from the composition's folder through the DevTools `Fetch` domain and fails all others, sets the viewport to the composition's size at a device scale of 1 with a transparent default background, and captures each frame as a PNG screenshot. Frames are `PixelFormat::Rgba` (straight alpha), tagged sRGB like CSS colours, so `#FF7A45` in a page matches the same colour in a FossCut text style. The renderer converts R'G'B'A frames to premultiplied linear light; FFmpeg decodes ProRes 4444, PNG and GIF with alpha the same way, Y'CbCr with its own matrix.
4. **The time contract.** A script runs before the page's own scripts and gives it FossCut's clock: `performance.now()`, `Date`, `requestAnimationFrame` timestamps and timers read composition time, which starts at 0 and stands still until FossCut moves it.
   - **Pages without a hook** are stepped one composition frame at a time from frame 0: due timers run, then one round of animation frame callbacks, then promise reactions settle. GSAP follows the clock through its ticker, with lag smoothing switched off. CSS animations, CSS transitions and Web Animations are paused and set to the time since they appeared; SVG animations, `<video>` and `<audio>` follow the clock. Frame n is therefore the same however frames are asked for: going back reloads the page and steps again, unless the page never used timers or animation frames.
   - **A page that defines `window.fosscut.seek(seconds)`** jumps straight to each frame's time: FossCut sets the clock, places CSS and Web Animations, calls the hook, awaits its promise (running animation frames at that time meanwhile) and runs one round of animation frames.
   - **Before every capture** FossCut waits for `document.fonts.ready` and for `<img>` elements to decode, up to 15 s each.
5. **Browser discovery.** `FOSSCUT_BROWSER`, then the `chrome-headless-shell` model in the models folder, then Google Chrome, Chromium, Microsoft Edge or Brave in their usual places on macOS, Windows and Linux. None found is `fosscut.web.browser_missing`, whose hint offers `fosscut models install chrome-headless-shell`: a manifest (task `browser`) of Chrome for Testing's macOS archives (Apple silicon and Intel) with pinned addresses, sizes and SHA-256 for every kept file (ADR-0033 item 2), installed only after the user agrees. Linux and Windows users install a browser themselves for now. The browser runs headless with `--host-resolver-rules=MAP * ~NOTFOUND`, software rendering, the sRGB colour profile and the DevTools endpoint on the loopback interface. On Unix it runs under a shell that ends it when FossCut's pipe closes, so it never outlives FossCut.
6. **Remotion, only the user's own** (`fosscut_engine::remotion`). For a folder whose `package.json` depends on `remotion` and has it installed, FossCut runs `npx --no-install remotion render <entry> <composition> <out> --codec=prores --prores-profile=4444 --pixel-format=yuva444p10le --image-format=png [--props=<file>]` in the project into the bundle's `renders/` folder, then imports the file as video. It never installs Remotion. Without confirmation it fails with `fosscut.web.confirmation_required`, whose details carry the command and this sentence for the user: Remotion is free for individuals and small companies but requires a paid company licence above that size. Progress comes from the `done/total` counts Remotion prints; cancelling ends Remotion's whole process group and keeps no file.
7. **Reach.** CLI: `fosscut web import <folder|file> [--width --height --fps --duration --name]`, `fosscut web remotion <project> <composition> [--props JSON] [--entry PATH] --yes` and `fosscut web browser`; `media import` takes compositions too. MCP adds no tool: `media_import` takes compositions in `files` with an optional `composition`, and `remotion: {composition, props, entry, confirm}` starts a background job (`kind: remotion`) that imports when done. `capabilities` lists `web.import` and `web.remotion`, a `web` section with the browser found, and the `fosscut.web.*` codes.

## Consequences

- Agents can show anything a browser draws, from typing search bars to WebGL, and keep editing it as an ordinary clip.
- Rendering costs a browser start (about 1 s) per decoder and roughly 30 ms (320x180) to 120 ms (1080x1920, debug build) per frame. Pages driven by timers or animation frames are slow to scrub backwards, since each step back reloads and replays them.
- Pixels depend on the browser's version and fonts: the same machine and browser give the same frames, another may not. Compositions should carry their fonts.
- Only explicitly timed work is deterministic: network requests, `requestIdleCallback`, workers and wall-clock reads outside `Date` and `performance` are not timed.

## Alternatives considered

- **A Chrome DevTools crate such as `chromiumoxide`:** a large async dependency tree for a few commands; a small client over a loopback WebSocket is enough.
- **Chrome's own virtual time and `HeadlessExperimental.beginFrame`:** only in the old headless mode, and it cannot go back in time.
- **`file://` pages:** modules and `fetch` are blocked there, and every local file would be readable.
- **Bundling or installing Remotion, or a headless browser:** licence and size, as above.

## Validation

- **Engine tests with Chrome:** a CSS animation, a seek hook and a page stepped by animation frames give the expected pixels at chosen frames in any order; transparent areas stay transparent; a `font-display: block` font is drawn on the first frame; two browsers give identical frames; a web clip composites over a lower track in frame grabs and exports. They skip without a browser unless `FOSSCUT_REQUIRE_BROWSER=1`.
- **Remotion:** a fake `npx` checks the command, confirmation, progress, failure, cancellation of the process group and the job's import; a real render runs with `FOSSCUT_REQUIRE_REMOTION=1`.
- **Before Accepted:** a maintainer checks the headless shell's distribution terms, and runs compositions on Windows and Linux.
